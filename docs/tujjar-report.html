تجّار المواشي — منصة بيع وشراء المواشي

منصة ويب كاملة لبيع وشراء المواشي في السعودية ودول الخليج، مبنية بالكامل وتم فحصها فعليًا (وليس فقط بناؤها) على متصفح حقيقي متصل بقاعدة بيانات Firebase فعلية — تسجيل حسابات حقيقية، نشر إعلان حقيقي بصورة مضغوطة، وتفعيل صلاحيات المشرف والتحقق منها.

🔗 tujjar-almawashi.web.app Next.js 16 · App Router Firebase (Firestore + Auth + Hosting) Tailwind CSS v4

01 ما تم تنفيذه

الصفحات العامة

الرئيسية بحقول بحث وأقسام وإعلانات مميزة، جميع الإعلانات مع فلترة وترتيب وترقيم صفحات، صفحة إعلان مفردة بمعرض صور وخريطة ومعلومات بائع، بحث متقدم بفلاتر سعر دقيقة، تسجيل دخول/تسجيل حساب، والشروط والأحكام بالنص المطلوب حرفيًا.

حساب المستخدم

تعديل الاسم ورقم الجوال، تبويبات للإعلانات (نشطة / مميزة / منتهية / مخالفة)، تعديل وحذف الإعلانات الخاصة.

لوحة تحكم المشرف

نظرة عامة بإحصائيات حية + قسم "أحدث البلاغات" (حصري للمشرف)، إدارة كاملة للإعلانات (تمييز/إخفاء/حذف نهائي)، إدارة المستخدمين (حظر/ترقية)، إدارة البلاغات، إدارة السلالات والمناطق، إدارة المشرفين، وإعدادات الموقع (بما فيها وضع الصيانة المُفعَّل فعليًا وليس شكليًا).

الأمان والصلاحيات

كل قواعد الوصول مفروضة داخل firestore.rules نفسها (RBAC حقيقي على مستوى قاعدة البيانات) وليس فقط في واجهة المستخدم — بمعنى أن تجاوز الواجهة لا يمنح أي صلاحية إضافية.

خلل حقيقي اكتُشف وأُصلح أثناء الفحص

المشكلة: صفحة الإعلان المفرد كانت بمسار ديناميكي كلاسيكي /ad/[id]. عند النشر الثابت (بدون سيرفر خلفي، تجنبًا لأي خطة دفع)، لا توجد وسيلة موثوقة لجعل المتصفح يستخرج المعرّف الحقيقي من الرابط لأي إعلان جديد — الأمر ظهر فقط عند التجربة الفعلية بإعلان حقيقي، وليس بالبناء وحده.

الحل: تحويل المسار إلى /ad?id=<المعرّف>، وهو أسلوب يعمل بثبات مع الاستضافة الثابتة دون الحاجة لأي خادم. تم اختباره وتأكيده على الرابط المنشور فعليًا بعد الإصلاح.

نقاط القوة

  • صلاحيات حقيقية على مستوى قاعدة البيانات، لا يمكن تجاوزها من الواجهة.
  • لا تكاليف استضافة أو تخزين — Firestore + Auth + Hosting كلها ضمن الخطة المجانية.
  • ضغط الصور من جهة المستخدم قبل الرفع، يقلل الحجم والتكلفة.
  • هوية بصرية متسقة بالألوان والخط المطلوبين في كل الصفحات.
  • تم اكتشاف وإصلاح خلل توجيه حقيقي أثناء الفحص، لا نظريًا فقط.

نقاط ناقصة وقيود معروفة

  • لا يوجد تحقق برقم الجوال (OTP) — التسجيل بالبريد وكلمة المرور فقط.
  • لا يوجد نظام دفع فعلي للإعلانات المميزة — التفعيل يدوي من لوحة التحكم حاليًا.
  • المدينة حقل نصي حر (لا قائمة معتمدة لكل منطقة)، لتفادي الحاجة لبيانات جغرافية كاملة.
  • لا اختبارات آلية (unit/e2e) ولا CI/CD حتى الآن.
  • تخزين الصور كنص Base64 داخل المستند مناسب للحجم الحالي، لكنه ليس بديلاً كاملاً لتخزين ملفات حقيقي إن كبر عدد/حجم الصور مستقبلاً.

04 اقتراحات تحسين لاحقة

  1. ربط بوابة دفع فعلية (مدى/Apple Pay عبر Moyasar أو Tap) لتفعيل الإعلانات المميزة تلقائيًا.
  2. إضافة تحقق برقم الجوال عبر Firebase Phone Auth عندما يصبح ذلك أولوية.
  3. الانتقال لتخزين الصور في Cloud Storage الحقيقي إذا فُعّلت خطة Blaze مستقبلاً — يرفع حد حجم/جودة الصور.
  4. إضافة صفحة تقييم فعلية للبائع (النموذج موجود بالبيانات لكنه غير مُفعّل بواجهة تقييم).
  5. ربط اسم نطاق مخصص (مثل tujjar-almawashi.sa) بدل الرابط الفرعي الحالي.

05 تحديثات بعد التقرير الأول

صور حقيقية بدل الرموز التعبيرية

استُبدلت أيقونات أقسام المواشي بالرئيسية وخلفية الهيرو بصور حقيقية مرخّصة استخدامًا حرًا (Wikimedia Commons وFlickr)، بشفافية 85% حسب الطلب. المصادر والتراخيص موثقة في public/images/CREDITS.md.

نظام صلاحيات ثلاثي: owner / admin / user

أُضيف دور "مالك النظام" (owner) منفصل عن "مشرف" — هو الوحيد القادر على ترقية/إلغاء المشرفين، وعلى الوصول لصفحتي "إدارة المستخدمين" و"إعدادات الموقع" (تختفيان تمامًا عن أي مشرف عادي، مع توجيه تلقائي عند محاولة الدخول برابط مباشر). القيد مفروض في الواجهة وأيضًا داخل قواعد Firestore نفسها — تم اختباره فعليًا بحساب مشرف تجريبي حاول تجاوز الواجهة عبر طلب مباشر لقاعدة البيانات ورُفض الطلب.

حالة نشاط المشرفين

صفحة "المشرفون" تعرض الآن حالة كل حساب (نشط / غير نشط) مع زر تفعيل/إيقاف مباشر، دون الحاجة للتنقل بين الصفحات.

زر رجوع في كل صفحة

أُضيف زر "رجوع" موحّد لكل الصفحات العامة وكل أقسام لوحة التحكم الثمانية — يرجع للصفحة السابقة فعليًا، ويوّجه لوجهة منطقية بديلة إن فُتحت الصفحة برابط مباشر بدون تاريخ تصفح.
