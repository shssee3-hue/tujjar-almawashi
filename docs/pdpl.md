# الامتثال لنظام حماية البيانات الشخصية (PDPL)

المنصة تعمل داخل السعودية ولتداول المواشي الداخلي فقط. جهة التحكم: مالك
المنصة (وثيقة العمل الحر). تنظّم SDAIA النظام.

هذا المستند = سجل أنشطة المعالجة (RoPA) + خطة الاختراق + سياسة الاحتفاظ +
قائمة ما يجب أن يؤكّده المالك. **ليس استشارة قانونية** — يُراجَع من مختص قبل
الإطلاق العام.

---

## 1) ما نُفّذ في المنتج

| البند | المكان |
|---|---|
| موافقة صريحة على سياسة الخصوصية عند التسجيل (مربع إلزامي) | `register/page.tsx`، `AuthGateModal.tsx` |
| صفحة سياسة خصوصية متوافقة (غرض + أساس نظامي + احتفاظ + حقوق) | `src/app/privacy/page.tsx` |
| حق الحذف: زر «طلب حذف حسابي وبياناتي» ينشئ `deletionRequests/{uid}` | `profile/page.tsx` |
| المالك يرى الطلبات المعلّقة وينفّذها خلال 30 يومًا | `dashboard/users/page.tsx` + `deleteUserPermanently` |
| حق التصحيح: تعديل الاسم/الجوال/بريد الدخول | `profile/page.tsx` |
| سحب الموافقة: إيقاف إظهار رقم التواصل | زر التواصل في `add-ad` + `adsPrivate` |
| تقليل الكشف: أرقام التواصل في سجل خاص لا يُقرأ إلا بشروط | `adsPrivate` + `firestore.rules` |

## 2) سجل أنشطة المعالجة (RoPA)

| البيانات | الغرض | الأساس | التخزين | الاحتفاظ |
|---|---|---|---|---|
| الاسم، البريد، الجوال، نوع الحساب | حساب + دخول + تواصل بشأن الخدمة | تنفيذ العقد | Firestore `users/{uid}` | مدة نشاط الحساب؛ حذف خلال 30 يومًا من قبول طلب الحذف |
| جوال/واتساب الإعلان | تمكين المشتري من التواصل | موافقة صريحة (تفعيل الزر) | Firestore `adsPrivate/{adId}` | حتى حذف الإعلان أو الحساب |
| نص/صور الإعلانات والتعليقات | العرض للزوار | تنفيذ العقد | Firestore `ads` / `comments` (صور Base64) | مدة تشغيلية بعد الانتهاء ثم حذف |
| قيمة البيع + صورة إيصال التحويل | مراجعة وتحصيل عمولة المنصة | تنفيذ العقد + مصلحة مشروعة | Firestore `commissions/{id}` (Base64) | للمدة اللازمة للإثبات المحاسبي ثم إتلاف |
| سجلات وصول تقنية / جلسة | تشغيل وأمان | مصلحة مشروعة | مزوّد الاستضافة / المتصفح | قصيرة، تلقائية |

**المعالِجون (Processors):** Google Firebase (مصادقة + قاعدة بيانات)،
Cloudflare (استضافة الملفات الثابتة). كلاهما بموجب شروط المعالجة القياسية.

## 3) نقل البيانات خارج المملكة

قاعدة بيانات Firestore قد تقع خارج السعودية. **تحقّق من الموقع:** Firebase
Console ← Firestore Database ← أعلى الصفحة يظهر الموقع (مثل `nam5` أو `eur3`
أو `me-central`). كلها خارج المملكة.

الأساس المعتمد حاليًا: النقل بالقدر اللازم لتقديم الخدمة، مع ضوابط المعالِج
التعاقدية والتقنية. الحل طويل المدى: منطقة Google Cloud داخل المملكة عبر
CNTXT.

> ⚠️ **تنبيه:** بند «نقل البيانات خارج المملكة» أُزيل من سياسة الخصوصية
> المنشورة (`/privacy`) في التعديل الأخير. النقل الفعلي لا يزال قائمًا (راجع
> أعلاه) — إزالة الإفصاح عنه لا تُلغي الالتزام النظامي بذكره. يُنصح بإعادته
> عند المراجعة القانونية القادمة.

## 4) خطة الاستجابة للاختراق

1. عند اكتشاف تسرّب/وصول غير مصرّح: عزل السبب فورًا (تدوير المفاتيح، سحب
   صلاحيات، تفعيل وضع الصيانة `maintenanceMode` إن لزم).
2. توثيق: ما تسرّب، متى، كم شخصًا تأثّر، الإجراء المتخذ.
3. إبلاغ **SDAIA** خلال **72 ساعة** من العلم (عبر القنوات الرسمية في
   sdaia.gov.sa)، وإبلاغ المتأثرين إذا كان التسرّب يشكّل خطرًا عليهم.
4. جهة الاتصال المسؤولة: __________ (يعبّئها المالك).

## 5) ما يجب أن يؤكّده / ينجزه المالك قبل الإطلاق العام

- [ ] تعيين جهة اتصال لحماية البيانات (اسم + وسيلة تواصل) وإضافتها في تذييل
      الموقع وفي البند 1 من سياسة الخصوصية والبند 4 أعلاه.
- [ ] مراجعة تعديل سياسة الخصوصية الأخير مع مستشار قانوني قبل الاعتماد
      النهائي — حذف بندَي «نقل البيانات خارج المملكة» و«الشكوى إلى SDAIA»
      قد يحتاج إعادة نظر (راجع البند 3 أعلاه).
- [ ] تأكيد أن نشاط «منصة وساطة بعمولة» يندرج ضمن وثيقة العمل الحر أو يحتاج
      سجلًّا تجاريًا (عبر خدمة عملاء منصة العمل الحر).
- [ ] التحقق من موقع Firestore وتوثيق أساس النقل خارج المملكة (البند 3).
- [ ] التحقق من متطلبات التسجيل في المنصة الوطنية لإدارة البيانات (SDAIA)
      لحجم النشاط.
- [ ] مراجعة سياسة الخصوصية والشروط من مستشار قانوني.
- [ ] جدولة حذف/إتلاف دوري للإيصالات والحسابات الخاملة (يدويًا الآن، أو
      Cloud Function عند ترقية Blaze).
- [ ] بعد ترقية Blaze: نقل الإيصالات والصور إلى Storage بقواعد حجم/نوع
      وصلاحية قراءة محصورة (تقليل تعرّض البيانات المالية).
